# 文件发送修复与微信版本匹配

本分支基于上游 `v39.3.3`，基线提交为 `f41b248023fce21fe1c828b4f60e34d90b9e6531`，适配 Windows 微信 `3.9.11.25 x64`。这是一份源码修复，尚未发布包含该补丁的 DLL 或安装包。

## 版本核对

2026-10-15 读取本机已安装程序的文件版本资源，结果如下：

| 核对项 | 结果 |
| --- | --- |
| `WeChat.exe` 文件版本 | `3.9.11.25` |
| `WeChatWin.dll` 文件版本 | `3.9.11.25` |
| `WeChatFerry/spy/spy.h` 的 `SUPPORT_VERSION` | `3.9.11.25` |
| `WeChatFerry/spy/spy.rc` 的适配产品版本 | `3.9.11.25` |

`WeChatFerry/com/util.cpp` 中 `GetFileVersion` 读取 `VS_FIXEDFILEINFO.dwFileVersionMS` 和 `dwFileVersionLS`；`GetWeChatVersion` 对微信核心 DLL 使用此值。`WeChatFerry/spy/spy.cpp` 再将其与 `SUPPORT_VERSION` 做完整字符串比较。因此本次核对采用文件版本 `3.9.11.25`，而非微信资源中另一个产品版本字段 `3.9.11.1000`。

修复保留启动版本校验、函数偏移和文件发送调用参数。该分支继续使用 `v39.3.3` 的微信适配代码；不能将其他微信版本的 DLL 直接混用。

## 根因及代码修改

旧文件发送函数以 `WxString` 包装 `std::wstring::c_str()`，两者共用同一缓冲区。微信文件发送函数释放并清空传入的字符串字段后，原 `std::wstring` 仍持有旧地址，退出作用域时再次释放，导致 `0xc0000374` 堆损坏。

实际崩溃转储中，`spy.dll+0x37d30` 位于文件路径字符串析构的释放返回位置；恢复的栈对象显示微信参数指针及长度已清零，而原字符串仍持有缓冲区。此路径处理的是文件路径参数，复现不需要真实文件或大安装包。

修改范围：

- `WeChatFerry/spy/send_msg.cpp`：增加仅用于文件发送的 RAII 所有者，独立分配参数缓冲区。微信消费并清空参数后不再释放；提前失败或参数未被消费时回收，防止部分分配泄漏，并检查长度边界。
- `WeChatFerry/spy/send_msg.h`：文件发送函数返回状态，正常调用返回 `0`，分配失败返回 `-3`。
- `WeChatFerry/spy/rpc_server.cpp`：透传发送返回状态，避免分配失败后仍返回成功。

其他消息类型的内存规则保持原实现。状态 `0` 保留原有的调用成功语义，不等于收件人接收回执。

## 已有验证

修复前，在独立程序中提取原始发送函数，使用消费并清空参数的本机替身代替微信函数；ASCII 假路径即可复现 `0xc0000374`。

修复后，已有九组隔离回归通过：ASCII、中文、空路径、短路径、长路径、被调用方未消费参数、第一次分配失败、第二次分配失败和同进程重复调用 1000 次。分配失败不进入发送调用，重复调用结束没有跟踪到未回收的参数缓冲区。隔离程序不加载微信、不注入进程、不发送消息。

按本轮要求，仅继续核对源码、文件版本、补丁和编码，没有执行真实微信发送测试。完整 `spy.dll` 构建、实际加载兼容性和端到端发送尚待验证，现有结果不能替代这些验收。手动上传后出现的重新登录提示缺少同类崩溃证据，本修复不对该现象作已解决的结论。
